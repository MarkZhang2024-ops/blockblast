# 算法参数

所有数值都在 `assets/scripts/config/GameConfig.ts`。改完后重新预览即可，不需要改算法结构。

## 棋盘和分数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `board.size` | 8 | 棋盘边长 |
| `score.cell` | 0 | 只放置不得分 |
| `difficulty.pointsPerLevel` | 400 | 每累计这么多分，等级加 1 |
| `score.clearCell` | 2 | 每消除一格。行和列的交点只算一次 |
| `score.lineBonus` | 12 | 每一条被消除的行或列 |
| `score.multiLineBonus` | 8 | 同一次消除里，从第二条线开始每条追加 |
| `score.comboStep` | 0.5 | 连击每增加 1，倍率增加的值 |
| `score.maxMultiplier` | 4 | 倍率上限 |

没有消除时得分为 0，连击归零。

有消除时，只计算被消掉的格子：

```text
连击 = 之前连击 + 1
倍率 = min(最大倍率, 1 + (连击 - 1) * comboStep)
消除分 = 消除格数 * clearCell + 线数 * lineBonus + max(0, 线数 - 1) * multiLineBonus
本步得分 = round(消除分 * 倍率)
```

连续放置都发生消除时连击才会累加。中间有一步没消除，连击回到 0。

## 难度

等级只由当前分数决定，每 400 分一级：

| 分数 | 等级 | 发牌倾向 |
| --- | --- | --- |
| 0–399 | 1 | 简单 |
| 400–799 | 2 | 普通 |
| 800–1199 | 3 | 困难 |
| 1200 以上 | 4 起 | 专家。等级继续随分数增加，发牌保持专家 |

界面显示「等级 N」。重开后分数回到 0，等级回到 1。

1 级发简单形状，2 级普通，3 级困难，4 级及以上专家。等级继续升高时，专家权重会再略微偏向大块。占用率高时，小块权重仍会提高，避免直接死局。

## 方块目录和加权随机

`BlockCatalog` 提供 17 种基础形状：单格、二连、三连、小拐角、方块、四连、T、L、S、五连、十字、长 L、U、大 T、P、矩形和九宫。生成时会旋转和镜像，并去掉重复朝向。

`BlockGenerator.weightForShape` 用基础权重乘上难度和盘面系数：

- 简单偏向 3 格及以下，压低 5 格及以上
- 普通加强 3 到 4 格
- 困难和专家加强大块，减少单格和二连
- 占用率达到 `evaluator.crowdedOccupancy`（0.72）时，小块权重再提高，避免直接死局
- 碎片化高时，3 格及以下再提高

抽取使用权重和，不是固定轮换。同一随机种子得到同一组方块。

## 前瞻搜索

`LookaheadSolver.searchSequence` 对三个方块的 6 种顺序做有限宽度搜索。每一步只在棋盘副本上调用 `resolvePlacement`。进入搜索时会先复制棋盘。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `lookahead.beamWidth` | 3 | 每一层保留的状态数 |
| `lookahead.branchLimit` | 5 | 每个状态最多展开的高分落点 |
| `lookahead.maxNodes` | 260 | 一次搜索的展开上限，超出就剪枝 |

落点先用行列补满数量打分，不复制棋盘。只有被选中的分支才真正模拟。放置列表按「棋盘占用哈希 + 形状签名」缓存在这一次搜索内部。

搜索只在发下一组方块时运行。拖动预览只调用一次合法位置求解，并在手指移动时重复使用。

## 公平性

`FairnessValidator` 用上面的搜索结果过滤一组三个方块。

拒绝原因：

- `none-fit`：棋盘还有空格，但这三块现在一块都放不下
- `no-path`：连续可放置块数低于当前要求
- `too-easy`：专家难度、盘面还很空，三块却都只有 1 或 2 格
- `shreds-board`：简单或普通难度下，最好的走法会把中前期盘面打得过碎

连续放置要求：

- 空格不超过 3 个，或占用率达到 0.82：至少 1 块
- 困难、专家：至少 1 块
- 简单且占用率低于 0.5：三块都要有路径，否则至少 2 块
- 普通且占用率低于 0.42：三块都要有路径，否则至少 2 块

## 候选生成

`GenerationPipeline.generateRound` 的流程：

1. 复制棋盘并评估空间。
2. 按当前难度权重随机产生 `generator.candidateCount`（12）组候选。
3. 每组做公平性验证和前瞻。
4. 合格组按和目标难度的距离做加权随机，温度是 `generator.selectionTemperature`（0.18）。温度越小，越贴近目标难度。
5. 如果没有合格组，就放宽到「至少有一块现在能放下」。
6. 仍然没有，就从当前确实放得下的朝向里救援三块。

救援仍然是加权随机，不是固定顺序。棋盘真的没有空格时，对局在发牌前结束。

## 空间评估

`BoardEvaluator` 计算占用率、每行每列填充、接近消除的行列、四连通空洞数量、最大空洞、孤立空格、碎片化和边缘压力。

接近消除的阈值是 `evaluator.almostFullRatio`（0.7）。碎片化同时看空洞块数量和孤立空格比例。评估只读棋盘。
